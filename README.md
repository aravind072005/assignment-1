## 1. Explain the Difference Between QA and QC

QA (Quality Assurance) and QC (Quality Control) are two important processes in software testing used to ensure software quality.

| QA (Quality Assurance)                    | QC (Quality Control)                        |
| ----------------------------------------- | ------------------------------------------- |
| QA is a process-oriented activity.        | QC is a product-oriented activity.          |
| It focuses on preventing defects.         | It focuses on identifying defects.          |
| It improves the development process.      | It checks the quality of the final product. |
| It is mainly a preventive approach.       | It is mainly a corrective approach.         |
| It includes process audits and standards. | It includes testing and defect reporting.   |
| Example: Reviewing the testing process.   | Example: Testing a login page to find bugs. |

Conclusion: QA prevents defects by improving processes, whereas QC detects defects by checking the product.

## 2. Explain Any 5 Principles of Software Testing

There are seven fundamental principles of software testing. The following are five important principles.

### 1. Testing Shows the Presence of Defects

Testing can identify defects in software, but it cannot prove that the software is completely defect-free.

Example: Testing a login page may reveal an incorrect password error, but it cannot guarantee that no other defects exist.

### 2. Exhaustive Testing Is Impossible

Testing every possible input, condition, and scenario is usually impossible because of time and cost constraints. Therefore, testers select important test cases based on risk and priority.

Example: A banking application has many possible input combinations, so testers focus on critical transactions and important scenarios.

### 3. Early Testing Saves Time and Cost

Testing should begin as early as possible in the software development life cycle. Finding defects early makes them easier and cheaper to fix.

Example: Identifying a requirement error before coding prevents expensive changes later.

### 4. Defect Clustering

A small number of modules usually contain most of the defects. Testers should focus more on modules that have shown frequent defects.

Example: If the payment module contains many bugs, testers should give it additional testing attention.

### 5. Pesticide Paradox

Repeating the same test cases again and again may eventually stop finding new defects. Testers should regularly review and update test cases.

Example: Adding new test cases for invalid inputs, different browsers, and unusual user actions can reveal additional bugs.

Conclusion: These principles help testers plan effective testing, identify defects early, reduce costs, and improve software quality.
